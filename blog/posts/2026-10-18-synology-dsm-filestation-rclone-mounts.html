Making rclone mounts usable in Synology DSM File Station

I have been trying to find a clean solution for using Synology DSM File Station with rclone mounts for a while now.

The rclone side of things worked. From the command line, I could mount a remote filesystem and work with the files without any real trouble. The problem was what happened next: DSM File Station did not treat the mount like a normal location. That meant I could not reliably use the DSM interface to browse, move, or manage files on the mounted remote storage.

For someone who uses a Synology NAS every day, this was frustrating. The command line gave me access, but I still wanted the seamless UI experience that File Station is supposed to provide.

The missing piece

After trying a few different approaches, I ended up writing a small wrapper around fusermount3. The wrapper changes how DSM sees the mount, which makes File Station treat it differently. Instead of seeing a mount that it cannot properly manage, File Station can work with it as a usable file location.

That is the whole idea behind the wrapper: keep the rclone mount, but present it to DSM in a way that plays nicely with File Station.

Example rclone mount

Install the wrapper as an executable named fusermount3 somewhere on the system PATH. For example: 

install -m 755 /path/to/fusermount3 /usr/local/bin/fusermount3

Once that file is in place, the rclone command itself can stay familiar: 

rclone mount remote:path /volume1/rclone/remote \
  --vfs-cache-mode full \
  --allow-other \
  --daemon

Replace /path/to/fusermount3 with the location of the downloaded wrapper. Replace remote:path with the name of your rclone remote and the path you want to mount. Replace /volume1/rclone/remote with an existing folder on your Synology. The important part is that the mount is created through the wrapped fusermount3. rclone still performs the mount, while the wrapper changes how DSM presents it to File Station.

After the mount is active, open File Station and browse to the mount point. You should be able to work with the remote files through the DSM interface, including moving and organising them.

Still a work in progress

I am still working through this setup and there are some areas that need more testing. One issue I have observed so far involves accessing the mounted files over SMB from macOS. Windows access over SMB appears to work as expected, but the macOS behaviour is not yet as reliable, so I am continuing to investigate that separately.

For now, I would treat this as a practical workaround rather than a completely finished solution. The File Station integration is the part I was trying to solve, while SMB compatibility—especially with macOS—still needs further testing.

You can find the script here: DSM/fusermount3 on GitHub

Why this is useful

With the wrapper in place, I can use the command line for mounting and automation, while still using File Station for the everyday tasks that are much nicer in a GUI:

  • Browsing the remote files through DSM
  • Moving and organising files with File Station
  • Managing files without switching between SSH and the DSM interface

It is a small change, but it closes the gap between a working CLI mount and a mount that feels properly integrated into DSM.

In summary

The issue was not that rclone could not mount the remote storage. It was that DSM and File Station did not recognise or handle the mount in the way I needed. The fusermount3 wrapper solves that by changing how DSM sees the mount, giving me the File Station experience I had been looking for.

If you are using rclone mounts on Synology and have run into the same File Station limitations, the wrapper may be worth trying. As always, test it with your DSM and rclone setup before relying on it for important data.
